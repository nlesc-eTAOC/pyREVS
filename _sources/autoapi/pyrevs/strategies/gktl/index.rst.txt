.. py:class:: GKTLDatabaseExtension

   Bases: :py:obj:`pyrevs.database.StrategyDatabaseExtension`


   An extension class for the GKTL strategy.

   An extension of the database to store GKTL-specific
   data. To be able to checkpoint a sampling run with GKTL,
   and to compute unbiased estimates from the biased ensemble,
   one need to store/read the following attributes.

   At each resampling step n, the clone weights are W_i = exp(k * dA_i)
   and the normalization factor is R_n = mean(W_i). The (unbiased) estimate
   of the expectation of an observable O of the trajectories is then:

       E[O] = 1/N sum_i O_i exp(-log_tilt_i) prod_n R_n

   where log_tilt_i = k * sum_n dA_i,n along the ancestry of clone i.

   :ivar _iteration_count: number of completed resampling steps
   :ivar _cur_time: time of the last resampling step
   :ivar _k: the bias amplitude
   :ivar _log_norm: log of the normalization factor R_n of each resampling step
   :ivar _log_tilt: accumulated log-tilt of each clone along its ancestry
   :ivar _window_start: start time of the current resampling interval for each clone
   :ivar _ancestors: parent index of each clone, for each resampling step
   :ivar _times: time of each resampling step

.. py:class:: GKTL(fmodel_t: Any, runtime_cfg: pyrevs.core.RuntimeConfig, runner_cfg: pyrevs.runner.RunnerConfig, strategy_cfg: pyrevs.strategies.gktl.config.GKTLConfig, deterministic: bool)

   Bases: :py:obj:`pyrevs.strategies.base.BaseSamplingStrategy`


   A strategy class implementing GKTL.

   The Giardina-Kurchan-Lecomte-Tailleur algorithm evolves an ensemble of
   trajectories and, at fixed resampling intervals, kills or clones each of them
   according to a weight exp(k * dA), where dA is an observable increment
   over the interval. This biases the ensemble toward large values of the
   observable. The bias is accounted for when computing estimates (see
   :class:`GKTLDatabaseExtension`).

   Trajectories that converge (reach the target score) before the end time
   are frozen: their observable increment is zero over later intervals.

   .. rubric:: Notes

   This strategy relies on time management provided by
   BaseSamplingStrategy (e.g. ``self._end_date``, ``elapsed_time()``).
